# CC-LLM 辅助预训练方案

> 2026-10-18 实施校对：源代码已有音形 schema v2 修复及 `pgca_enabled` 旁路。在此基础上实现上下文模块、辅助头与 ms-swift 插件，当前入口为 `scripts/train/ms_swift/cpt/README.md`；框架在 `scripts/train/ms_swift/env/` 普通安装，不把项目脚本搬到外部框架仓库。模型名采用 `B-PGCA`，Phase1/2 分别为 `M-ALIGN` / `M-CPT`，训练产物位于 `outputs/train/<模型名>/`。旧训练脚本的 `2e-5` 学习率不作为新实验默认值，下文三阶段日程是新脚本依据。

本版固定采用：**保留单汉字 Tokenizer 和无 gate 的 PGCA 残差融合；在静态音形特征与 PGCA 之间加入共享的轻量因果 Transformer；Phase2 联合优化语言建模、下一 token 字音预测、下一 token 字形属性预测。**

这里的“下一 token”始终指紧邻的 \(x_{t+1}\)，仅当它是汉字且对应属性有效时计算辅助损失，**不跨过标点或英文寻找后面的汉字**。

这是一套待验证的研究方案，不预设它一定能修复当前 benchmark 退化。ChineseBERT 支持将音形信息用于中文表示学习，PLOME 支持引入发音预测目标；但二者不能直接证明下面这套 decoder-only 改造的收益，因此需要通过独立消融验证。[ACL Anthology](https://aclanthology.org/2021.acl-long.161/)

## 1. 总体结构与设计边界

整条计算路径分为两部分：

**输入侧：汉字 → 静态音形特征 → 轻量因果上下文编码器 → 上下文化音形 memory → PGCA → 主干隐藏状态。**

**输出侧：最终隐藏状态 → 原 LM Head、字音预测头、字形属性预测头。** 辅助头只参与训练与专项诊断，不向生成文本中添加拼音或字形标记。

当前 `feature_embedding.py` 为每个位置生成若干拼音候选 slot 和一个字形 slot；每个拼音 slot 已融合完整拼音、声母、韵母、声调，字形 slot 则融合笔画数、部首笔画组合、结构类别。新结构保留这一接口，不把候选先压缩成一个向量后直接交给 PGCA。

| 项目 | 本版确定的处理 |
|---|---|
| 主干 | Qwen3-1.7B，保持原 Self-Attention、MLP、LM Head |
| PGCA 融合 | 保留直接残差相加，不恢复可学习 gate |
| 音形上下文编码器 | **4 层、512 隐藏维度、8 个注意力头**，全模型共享一套 |
| PGCA memory | 保留“多个完整读音候选＋一个字形结构 slot”，维度与现有 PGCA 一致 |
| 字音辅助任务 | 预测下一汉字的**带调完整拼音**，多音字采用候选集合监督 |
| 字形辅助任务 | 预测下一汉字的笔画数、部首笔画组合、结构类别 |
| Phase1 | 主干适配新 Tokenizer，音形分支旁路并冻结，不计算辅助损失 |
| Phase2 | 开启音形分支，先短暂适配新增模块，再联合全参数 CPT |

**构建前必须使用已验收的音形 schema v2。** 候选、未知标签与特殊音节修复已经落地；新构建读取 manifest 中的候选宽度，当前默认 16，而不是硬编码 8。语义 tokenizer 和 token ID 不变。上下文网络不能选择一个不存在的候选，辅助目标也不能使用旧的错误标签。

## 3. Phase2 辅助目标：预测下一 token 的音形属性

### 3.1 统一预测位置和输出接口

三个任务都使用**主干最后一层、最终归一化之后的隐藏状态 \(h_t\)**：

| 预测头 | 输入 | 输出目标 |
|---|---|---|
| 原 LM Head | \(h_t\) | \(x_{t+1}\) |
| 新字音头 | \(h_t\) | \(x_{t+1}\) 的带调拼音 |
| 新字形头 | \(h_t\) | \(x_{t+1}\) 的字形属性 |

辅助头使用独立的轻量 MLP：`D → 256 → 对应类别数`，中间采用 SiLU。字形头共享一个 256 维中间表示，再分成三个分类器。分类器参数在模型内部注册，不放在训练脚本外部单独调用。

**特征输入与监督标签严格分离：**输入分支只查询 `input_ids` 对应的当前位置特征；辅助标签由 `labels[:, 1:]` 查询得到。不能把下一 token 的特征提前传入上下文编码器。

### 3.2 字音任务：采用带调拼音分类，不重复叠加声韵调损失

与早期草案相比，首版将字音监督收敛为**一个带调完整拼音头**，例如 `hang2`、`xing2`、`zhong4`。不再同时增加完整拼音、声母、韵母、声调四套损失，避免重复计权以及多音字属性组合不一致。

预测头对**整个合法拼音词表**做 softmax。对目标汉字 \(y_t=x_{t+1}\)，设其合法候选集合为 \(\mathcal P(y_t)\)，单位置损失采用：

\[
\ell_{\mathrm{phon},t}
=
-\log\sum_{p\in\mathcal P(y_t)}
P_{\mathrm{phon}}(p\mid h_t).
\]

这里 \(P_{\mathrm{phon}}\) 是全拼音词表上的概率分布，\(p\) 是一个带调完整读音。候选集合只参与损失计算，**不能先把 softmax 限制在目标字的候选内部**，否则候选概率和恒为 1，损失会退化。

单音字时，这就是普通交叉熵；多音字时，任何合法候选都可获得概率质量。实现使用 `log_softmax + gather + logsumexp`，不通过先求小概率再取对数计算。

这项监督有明确边界：**它训练的是“下一汉字对应的合法读音集合”，不是“该语境下唯一正确的发音”。** 没有可靠上下文 G2P 标签时，不能宣称已经监督了多音字消歧。首版不对 10B 语料重新生成自动拼音标注，也不把候选列表第一项强行当作真值。

### 3.3 字形任务：预测现有结构属性，不宣称重建完整字形

首版直接利用已验证的现有字段：

| 子目标 | 标签字段 | 处理方式 |
|---|---|---|
| 笔画总数 | `stroke_count_id` | 类别预测，不采用连续值回归 |
| 部首笔画组合 | `radical_stroke_id` | 对现有组合码分类，不误称为单独部首预测 |
| 字形结构 | `structure_id` | 对已有结构类别分类 |

每个子目标独立屏蔽未知标签。某字缺少结构类别，但笔画数有效，仍计算笔画数损失。类别数量由修复后的词表动态决定，不硬编码此前的 3100、1047 等旧数值。

**这是“字形属性预测”，不是图像重建、笔顺生成或逐笔画序列预测。** 当前数据并未提供这些更强目标所需的完整监督。

### 3.4 总损失及归一化

设 \(\Omega\) 为本次优化统计范围内所有有效 next-token 预测位置，\(N=|\Omega|\)。位置 \(t\) 的字音有效标记为 \(m_t^p\)，三个字形属性的有效标记为 \(m_{t,r}^g\)，其中 \(r\in\{1,2,3\}\)。

\[
\begin{aligned}
L_{\mathrm{CLM}}
&=\frac{1}{N}\sum_{t\in\Omega}
-\log P_{\mathrm{LM}}(y_t\mid h_t),\\[2mm]
L_{\mathrm{phon}}
&=\frac{1}{N}\sum_{t\in\Omega}
m_t^p\,\ell_{\mathrm{phon},t},\\[2mm]
L_{\mathrm{glyph}}
&=\frac{1}{3N}\sum_{r=1}^{3}\sum_{t\in\Omega}
m_{t,r}^g\,\operatorname{CE}
\left(P_{\mathrm{glyph},r}(\cdot\mid h_t),a_{t,r}\right),\\[2mm]
L_{\mathrm{total}}
&=L_{\mathrm{CLM}}+0.05L_{\mathrm{phon}}+0.02L_{\mathrm{glyph}}.
\end{aligned}
\]

其中，\(a_{t,r}\) 是目标汉字的第 \(r\) 个字形标签，CE 为交叉熵。非汉字、未知属性、padding、`labels=-100` 和被屏蔽的跨文档边界不产生相应辅助损失。

**三个优化损失共用 CLM 的有效 token 分母。** 这样英文 batch 自然只有 CLM，不会因为汉字很少就突然放大少量辅助样本的权重。日志另外报告按有效字音／字形监督数量归一化的平均损失和准确率，用于比较任务学习情况。

`0.05/0.02` 是首轮固定起点，不代表辅助梯度一定只占主任务的 7%。仍需记录加权损失比例及分支梯度；辅助损失下降也不等于 PGCA 贡献增大，因为主干自身可以学习这些属性。

## 4. 训练日程、分支启用与稳定初始化

保持 **Phase1 1B、Phase2 10B** 总预算。将 Phase2 的前 100M 划为新增模块适配，不额外增加一轮数据预算。

| 阶段 | Token 预算 | 前向计算与训练范围 | 目标与初始学习率 |
|---|---:|---|---|
| Phase1 | 1B | PGCA／上下文编码器旁路并冻结；训练主干及语义输入输出层；辅助头冻结 | CLM，主干 `1e-5` |
| Phase2-A | 100M | 开启完整音形路径；冻结主干参数，训练音形模块、上下文编码器、PGCA、辅助头 | 三任务；新增模块 `5e-5` |
| Phase2-B | 9.9B | 全部解冻，联合 CPT | 三任务；主干 `1e-5`，新增模块 `3e-5` |

辅助权重在 Phase2-A 的前 **10M 有效训练 tokens** 内从零线性升至 `0.05/0.02`，之后保持固定。各阶段重新建立 optimizer／scheduler；Phase2-B 使用参数组区分学习率。数据内容配比保持现有方案，不同时引入新的数据课程，以免混淆架构与数据收益。

实施采用优化步开始时的累计有效监督 token 数设置该步权重，梯度累积窗口内权重不变。累计数保存在 checkpoint 的 `auxiliary_trained_tokens` buffer，不能由 step 数乘固定序列长度估算。A/B 数据先按固定 seed 打乱，再按有效 `labels[1:]` 划分；边界样本允许复用输入上下文，但两段监督位置不重叠。为避免 DDP 自动重复最后几个样本，训练缓存补齐到 `world_size × per_device_batch_size` 的整数倍，补齐行显式标记且所有 labels 为 -100，不计入 token 预算。

1B/10B 是目标规模和默认训练上限，不能冒充已有语料的实际有效监督数量。数据不足时直接使用全部可用目标并报告请求量、实际量和缺口，不因短缺而停止，也不补重复文本凑数。`PHASE1_TOKENS=0` 表示不设上限、消费全部可用语料。Phase2-A 默认 100M，B 使用实际总量扣除 A 后的剩余部分；A 必须小于实际总量，保证 B 非空。

**冻结主干参数不意味着把主干 forward 包在 `torch.no_grad()` 里。** Phase2-A 仍需要通过 PGCA 后面的主干计算传播梯度，才能训练插入分支。

### 无 gate 条件下，采用零初始化输出投影

新实验构建时，将各层 PGCA 的 `o_proj.weight` 和 bias 初始化为零；其他 PGCA 投影、音形编码器及上下文模块正常初始化。这样 Phase2 首次打开时，PGCA 输出为零，不会立即向已对齐主干注入随机扰动。

这没有增加 gate，运行公式仍是直接相加。其梯度行为是：**第一步主要更新 `o_proj`，之后内部 Q/K/V 与上下文编码器开始获得有效梯度**；不能用“第一步内部梯度为零”判断模块失效。

对应地，现有构建验收需要允许指定 PGCA 输出投影为零，不能再把所有零矩阵统一视为初始化错误。此规则只用于**新实验初始化**，不能在加载已经训练好的 checkpoint 时重新执行。

首版不默认加入模态 dropout、额外对比学习或字形扰动恢复任务。先验证两个核心改动，避免同时改变过多因素。

## 5. ms-swift 4.7.0.dev0 接入与推理工程

### 5.1 采用项目插件组合损失，不直接依赖 `outputs.loss` 相加

我核对的 ms-swift 4.7 开发版在启用自定义 loss、`loss_scale` 等路径时，会先从输入中移除 `labels`，随后重新计算损失。因此，**只在模型中写 `loss = clm + auxiliary` 不能覆盖所有训练路径；只以 `labels is not None` 判断是否计算辅助头，也可能失效。**

正式接入分工如下：

| 位置 | 职责 |
|---|---|
| 模型 `forward` | 在原 LM logits 外，可返回 `phonetic_logits`、三个 `glyph_logits`；所有分类头在正常模型 forward 内执行 |
| 项目自定义 Template | 训练／验证时显式传入 `return_aux_logits=True`；纯生成时关闭 |
| 项目 `BaseLoss` 子类 | 接收 outputs 和 labels，执行统一 shift、属性查表、mask、CLM 与辅助损失组合 |
| 统计模块 | 累计各损失的分子、有效监督数和准确率，区分训练总损失与纯 CLM 验证指标 |

ms-swift 提供 `BaseLoss` 和 `--loss_type` 接口，可以通过外部插件注册；不需要修改安装包中的 Trainer。[swift.readthedocs.io](https://swift.readthedocs.io/en/v4.2/Customization/Architecture.html)

插件计划命名为 `cc_llm_multitask`，通过 `--external_plugins` 加载。首版关闭 `packing`、`padding_free`、sequence parallel、Liger loss 和 `use_logits_to_keep` 优化，先保证三条预测路径的位置严格一致；这些优化应在对应一致性测试通过后逐项恢复，而不是默认假定兼容。

**分布式与梯度累积必须沿用有效 token 总数归一化。** 不能各卡分别对辅助损失取均值后随意相加，也不能在插件和 Trainer 中重复乘 `world_size`。验收时用同一批样本比较单大 batch、梯度累积、DDP 的损失和梯度。

全英文 batch 或某项属性没有有效标签时，对应辅助损失返回与计算图连接的零值，既不产生 NaN，也避免有条件跳过辅助头造成 DDP 参数使用不一致。

### 5.2 不重建预训练语料，新增的是标签索引

普通训练文件继续保存 `input_ids`、`labels` 和必要的边界信息。辅助标签由**固定、只读的 token-ID 属性表**查询获得，不把拼音与字形复制到每条语料中，不在训练循环调用 pypinyin，不重新对 10B 文本跑 G2P。

新增保存的元数据应包括合法输出类别映射、各属性有效 mask、特征版本与哈希。只要语义 Tokenizer 和 token ID 没变，原有 tokenized corpus 可以复用；音形表变化时重建的是特征与辅助标签索引。

验证必须分别记录 `eval_clm_loss`、`eval_phon_loss`、`eval_glyph_loss` 和总损失。**PPL 只能由纯 CLM loss 计算，不能对三任务总损失取指数。** Checkpoint 选优以固定验证集上的纯 CLM 指标为基础，结合定期任务评测，避免只因辅助头更容易拟合就选中主任务退化的模型。

插件额外记录各任务有效监督计数、按其监督数归一化的诊断 loss/accuracy、加权辅助/CLM 损失比及主干/分支梯度范数。验证时先按样本汇总，再通过 Accelerate 去掉分布式尾部重复样本，最后累计分子/分母；不能直接平均每个 batch 的 loss。Phase2-A 使用最后 checkpoint 进入 B，Phase1/B 则按 `eval_clm_loss` 选优。

### 5.3 上下文编码器必须配套增量推理缓存

旧 PGCA 只读取当前 token 的静态属性，新编码器则依赖整个前缀。生成阶段不能只输入最新 token 的特征、却丢弃历史上下文。

正式实现增加遵循 Transformers Cache 接口的组合缓存，分别维护：

**主干 KV cache＋四层音形上下文编码器 KV cache。**

训练时关闭 cache；prefill 时编码整个 prompt，逐 token 解码时只计算新位置并读取音形历史 KV。两套 cache 必须同步处理位置长度、batch 重排和清理，不能复用相同的层索引或使用全局可变缓存。

尤其要注意增量解码时 Query 长度与 Key 长度不同，不能机械套用方阵训练时的 causal mask。PyTorch 的 SDPA 在非方阵情况下，`is_causal=True` 对应左上对齐，可能与有缓存解码所需的位置关系不同；必须根据实际位置构造 mask，并通过完整前缀与增量解码一致性测试。[PyTorch Docs](https://docs.pytorch.org/docs/main/generated/torch.nn.functional.scaled_dot_product_attention.html)

按本版 4 层、512 维、BF16 的完整多头 KV 估算，4096 长度下每条序列新增约 **32 MiB KV cache**。训练吞吐和显存仍需实测，不能仅凭新增参数少就宣称开销可忽略。

HF 路径应先完成验证；使用 vLLM 时，需要相应实现新增编码器和 cache，不能假定原 Qwen 或旧 PGCA 后端会自动执行新结构。

## 6. 验收、消融与正式执行顺序

### 6.1 上大规模训练前必须通过的测试

| 测试 | 验收要求 |
|---|---|
| 候选与标签 | 常见多音字候选完整；未知读音不产生轻声真值；辅助类别与索引版本一致 |
| 因果性 | 修改后缀不能改变前缀的上下文特征、PGCA 权重及 logits |
| Slot 保留 | 拼音候选仍可分别访问；无效 slots 始终为零；重排候选不改变最终结果 |
| Phase1 旁路 | 音形编码器和 PGCA 调用次数为零；保存后权重键仍完整 |
| 初始化与梯度 | 首次开启不改变主干输出；输出投影更新后，内部 PGCA／上下文模块获得梯度 |
| 辅助目标对齐 | 明确验证 \(h_t\) 对应 \(x_{t+1}\)，无重复 shift、越界查询或目标特征泄漏 |
| 空监督与分布式 | 无合法音形标签时不产生 NaN；单卡、累积与 DDP 的归一化一致 |
| 推理缓存 | 完整前缀重算与 cache 增量解码结果在相应精度容差内一致 |
| 序列边界 | 若后续启用 packing，主干与音形编码器采用相同文档隔离边界 |

### 6.2 核心消融只改变一个因素

所有实验从**同一个旁路训练得到的 Phase1 checkpoint**出发，使用相同 Phase2 文本、训练预算和下游 SFT 配置：

| 实验 | 静态 PGCA | 上下文编码器 | 音形辅助目标 | 作用 |
|---|---:|---:|---:|---|
| A：Char-only | 无 | 无 | 无 | 字符级主干参照 |
| B：Static-PGCA | 有 | 无 | 无 | PGCA 基础贡献 |
| C：Context-PGCA | 有 | 有 | 无 | 单独检验上下文化 |
| D：Static-PGCA＋Aux | 有 | 无 | 有 | 单独检验辅助监督 |
| **E：完整方案** | 有 | 有 | 有 | 检验两项改造能否协同 |

先以相同的 **0.5B–1B Phase2 预算**完成筛选，再决定进入完整 10B 的实验。最终研究结论还应补充参数量匹配或固定打乱“汉字—音形映射”的对照，区分真实音形结构收益与单纯增加容量的收益。

结果分三层报告：**语言建模与通用任务是否保持；CSC 等专项任务是否改善；PGCA 是否真正依赖语境与正确音形内容。** Attention 诊断继续采用正常、均匀权重、旁路、分别屏蔽拼音／字形的配对实验，不能只凭热力图或辅助准确率证明机制有效。

**正式执行顺序为：修复并冻结音形资源版本 → 实现旁路与稳定初始化 → 实现上下文编码器及 cache → 接入辅助头和统一损失 → 通过一致性测试 → 小预算消融 → 完整 Phase2。**

这套方案的关键不是把音形分支做得更深，而是让它同时具备三种可验证的性质：**输入特征可靠、上下文计算严格因果、训练收益能够被独立归因。**
