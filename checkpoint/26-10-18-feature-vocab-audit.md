### 问题一：常见多音字的候选缺失，是最优先修复项

本次文件中的实际映射如下：

| 汉字 | 当前全部候选 | 缺少的常用读音示例 |
|---|---|---|
| 行 | `xing2` | 银行、行业中的 `hang2` |
| 重 | `zhong4` | 重复中的 `chong2` |
| 长 | `zhang3` | 长度中的 `chang2` |
| 乐 | `le4` | 音乐中的 `yue4` |

这意味着：**新产物中的“行”，实际上只有一个拼音 slot 和一个字形 slot 有效；PGCA 不可能从中选出 `hang2`。** 即使后面增加上下文 Transformer，也不能通过 attention 选择一个根本不存在的候选。

当前源码虽然调用了 `heteronym=True`，但把导入和执行过程包在 `except Exception` 中；一旦发生异常，就静默退到只读取 Unihan 的 `kMandarin`。 而 `kMandarin` 主要记录最常用读音，最多区分大陆与台湾偏好的两个值，**不是完整多音字列表**；`kHanyuPinyin` 才包含更丰富的字典读音记录。[Unicode](https://www.unicode.org/reports/tr38/)

**当前分布高度符合“主要使用了 `kMandarin` 降级数据”的特征，但没有构建日志，不能断言一定是 pypinyin 没安装。** 下一步必须消除这种静默降级，并记录每个汉字的读音来源。

### 问题二：993 个未知读音被当成有效读音，还被赋予轻声

这些汉字的实际编码是：

```text
pinyin = <unk>
shengmu = ""       → 零声母
yunmu = <unk>
tone = 0           → 轻声
pinyin_mask = True
```

其中，**“未知读音”不等于“零声母＋轻声”**。如果直接把这套表用于下一汉字音形预测，就会给 993 个汉字提供错误的声母、声调监督。

原因也很明确：`split_pinyin("<unk>")` 返回空声母和声调 0；索引构建又仅按列表长度生成 `pinyin_mask`，没有排除 `<unk>`。

修复应当是：**未知拼音不参与真实读音 attention 选择；相关辅助标签设为忽略。** 字形中已经存在的有效笔画、部首结构信息仍然保留，不需要因为缺拼音而删除整个汉字样本。

### 问题三：特殊带调音节没有正确拆解

发现三个未统一格式的拼音词条，影响四个汉字：

| 当前词条 | 涉及汉字 | 当前错误处理 | 应统一的表示 |
|---|---|---|---|
| `ň` | 㕶 | 整体作为韵母，声调记为 0 | `n3`，单独拆出第三声 |
| `ḿ` | 呒、呣 | 整体作为韵母，声调记为 0 | `m2`，单独拆出第二声 |
| `ǹg` | 嗯 | 整体作为韵母，声调记为 0 | `ng4`，单独拆出第四声 |

这些不是需要删除的“乱码”，而是**当前归一化函数没有覆盖的带调音节辅音**。应补充转换和测试，而不是简单用 `[a-z]+` 将它们过滤掉。

另外，当前声韵拆分采用的是拼写拆分，例如 `ju4 → j + u`、`jun1 → j + un`，并把 `y/w` 当声母。这可以作为一种工程编码约定，但不能与严格声韵母定义混用。pypinyin 的严格约定会还原 `ü`、处理零声母以及 `iu/ui/un` 的省写形式。**既然后续要加入声韵预测辅助目标，建议在新实验中统一采用严格拆分，并对每个完整候选逐一拆解，保证声母、韵母、声调仍属于同一个读音。**[pypinyin.readthedocs.io](https://pypinyin.readthedocs.io/zh-cn/master/usage.html)

### 字形部分：未发现编号问题，但要明确表示范围

当前字形是**笔画总数＋部首笔画组合码＋结构类别**，不是字形图像，也不是逐笔画序列。

`radical_stroke_vocab` 的 3,100 个类别不是“3,100 个部首”，而是类似 `30.4`、`120'.8` 的组合属性；其中还包括简化形式标记。这个表示可以使用，但后续辅助头应叫“部首笔画组合预测”，不能误称为单独的部首预测。Unihan 对这些组合属性的定义见官方说明。[Unicode](https://www.unicode.org/reports/tr38/)
