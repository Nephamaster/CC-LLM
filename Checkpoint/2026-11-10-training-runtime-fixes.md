## 已实施

- 新增一个标准库运行文件 `scripts/train/runtime.py`，复用启动、阶段日志和检查点发布；每阶段的参数继续留在原脚本顶部，没有新增配置体系或 CPT common.sh。
- 单机未指定 `MASTER_PORT` 时，使用原生 torchrun standalone rendezvous；显式端口优先。空端口环境值在启动前移除，防止 argparse 将空字符串按整数解析。保留多节点环境参数的显式传递。
- 记录解释器、模型、输入/缓存、输出、实际分布式地址、world size、每卡 batch、累积及有效 batch。stdout/stderr 同步保存到显示的阶段日志；导入、模型、加载、编码和训练分别计时，没有训练总超时强杀。真实退出码/信号与容器级 OOM kill 增量分别记录；清理仅限本次启动器创建的进程组。
- 原生编码 cache 完成时复用 train/val，仅重新准备数据。准备通过临时目录完成后发布；原有未完成目录保留为 `.incomplete-*`，失败只清理本次临时目录。准备写入用文件锁串行化，避免同时发布；没有依赖版本锁、哈希校验或数据 manifest。原生 cache 不完整时明确指出 split 并保留文件，可用 `RAW_CACHE` 指定新导出路径。
- 顶层入口与阶段脚本统一使用 `TRAIN_ROOT`/CPT 路径。单阶段 `OUT` 生效；多阶段按各自默认子目录执行。显式阶段输入或恢复请求不会被旧完成指针跳过；上游重跑会刷新本次选中的依赖阶段。无新输入/上游更新时仍接续已完成结果，单阶段原生 vN 行为保留。
- 验证日志标明选优指标有限性与有效监督目标数；下游新增的目标计数复用 gather_for_metrics 去掉重复尾样本，不改变 loss 或 labels。每个运行目录保存 `checkpoint_selection.json`，说明 best/last 与原因，无有效 best 时明确回退到 last。Phase2-A 按设计取 last，原 `next_stage_model.txt` 接口保留。

## 验证结果

验证使用 `/tmp` 下的隔离环境和夹具，没有新增项目 tests 目录。Python 3.11.15，CPU PyTorch 2.15.0、Datasets 5.2.0、PyArrow 26.0.1、NumPy 2.4.6；另读取 ms-swift 4.6.0 的发行包源码，核对其 CLI 入口、打点方法及自定义指标合并方式，没有完整导入该框架运行模型。

- 真实 CPU torchrun/Gloo：两个重叠运行的两进程任务分配不同端口，各自保持 world_size=2；显式端口被保留，空 `MASTER_PORT` 默认值正常；实际 worker CLI 参数与传入参数一致。
- 真实 SIGSEGV：启动器返回 139 并保存信号及日志，清理其遗留子进程，独立会话中的对照进程不受影响。
- 真实 Arrow 缓存：复用原生导出、准备原子发布、旧部分数据保留、准备失败回滚、A/B 目标数与 dummy 约束通过；原来的卡数/batch 几何不匹配仍报错且不重建。
- 实际 Phase2-A shell + runtime + 真实缓存：完成 cache 检查/恢复后进入被拦截的训练调用，再次执行只 verify；几何变化在训练前失败，没有重新编码。模型导出与训练调用在该检查中被夹具拦截。
- 流水线夹具：自定义 TRAIN_ROOT、默认完成跳过、显式新输入、后续刷新、失败中断、单阶段 OUT 通过。
- 检查点选择：有限 best、NaN/Inf、零/无效目标计数、缺检查点、Phase2-A last 及原子指针发布通过。实际生产回调接入已用夹具验证。
- 下游 CPU tensor：有效目标计数、尾部重复样本处理、labels 不变、辅助损失设置、原编码并发策略及古汉语 macro 指标规则通过。
